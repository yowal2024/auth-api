# 测试与运行维护

项目的详细功能、兼容性边界、测试方法和备份恢复说明。开发、构建和首次部署见 [README](../README.md)。

## 测试

### 本地 IP 经纬度库

系统设置 → IP 定位服务：超级管理员统一选择本地 DB-IP、腾讯地图或高德地图。在线服务填写共用 KEY；本地 DB-IP 无需 KEY，先点击“安装”，完成后保存定位服务，后续点击“更新”获取官方月度版本。该页面显示本地库的安装状态、版本、更新进度及校验状态。应用信息保留“绑定 IP 区域”开关和各自的距离阈值，并提供系统配置入口。普通管理员不能访问系统配置或读取共用 KEY。

迁移 `0047_system_geo.sql` 将已有的相同服务配置和 KEY 自动迁移到系统设置；比较 KEY 时区分大小写。若不同应用使用不同配置，则继续沿用各自设置，系统页面提示选择统一配置，并允许载入某个已有应用的 KEY。只有保存后才统一生效，不擅自替换现有应用的定位服务。没有已配置服务时默认使用本地 DB-IP；安装完成前仍不能开启本地地域绑定。

系统定位配置保存后，下一次用户或卡密地域校验立即使用新配置，无需重启；各应用的绑定开关、距离限制、用户地点数上限及历史地点记录不变。旧应用字段 `geoProvider`、`geoKey` 继续保留用于升级兼容；一旦系统配置已统一，实际查询以系统配置为准，应用页保存不会修改共用服务。

使用 [DB-IP City Lite](https://db-ip.com/db/download/ip-to-city-lite)，数据按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可使用，署名 **IP Geolocation by DB-IP**；MMDB 读取使用开源 `maxminddb-golang`。覆盖中国及全球 IPv4/IPv6，提供区域估算经纬度；免费库不保证每个国内 IP 的市县精度，移动网络、公共 DNS、VPN 出口可能定位到其他地区。不可当作 GPS 使用。

更新仅从官方 HTTPS 地址下载，拒绝重定向，限制压缩/解压大小并校验 MMDB；失败保留旧版本，成功立即热切换，无需重启。当前实现为手动一键更新，不会后台定时下载。首次安装前不能启用本地地域绑定；私网、未收录 IP、缺失经纬度均报错，不使用伪造坐标放行。SDK 的用户/卡密模式均沿用原有地点数量和距离校验。

数据库保存在配置文件旁的 `data/geo/dbip-city-lite.mmdb`，可通过配置 `geo.local_dir` 指定目录；Docker 默认位于持久卷 `/app/runtime/data/geo`，不公开下载。更新期间保留新旧数据库，建议至少预留 512 MiB 内存和磁盘空间。本地查询不调用在线服务，也不读取旧 SQL 地理缓存，因此更新立即生效。

前端测试：`npm run test:local-geo`，覆盖系统配置的保存与失败保留、旧配置载入、下载进度、应用规则独立、权限和移动端布局。后端测试：`go test ./internal/geo ./internal/handler`；配置独立 MySQL 后，`TestGlobalGeoSettingsUpgrade` 验证旧 KEY 迁移及配置冲突，`TestRealDatabaseLifecycle` 验证保存后即时生效和单连接事务内的用户/卡密地域校验。可设置 `AUTH_RECOVERY_GEO_FIXTURE` 为官方下载的 `.mmdb.gz` 路径验证实际数据。系统配置接口为 `GET/POST /api/<入口>/system/geo`，仅超级管理员可访问；本地库接口为 `GET /api/<入口>/geo/local`、`GET /api/<入口>/geo/local/lookup?ip=...`、`POST /api/<入口>/geo/local/update`，均需要管理员会话，更新还要求超级管理员。

更新已有实例后，正常启动或重启服务即可自动应用增量数据库迁移。`auth-api -config config.yaml -migrate` 保留为可选维护命令，只执行迁移检查并退出，不启动 HTTP/HTTPS 服务。

客户端真实 HTTP 回归：设置 `TEST_ADMIN_PASSWORD` 后运行 `node scripts/client-lifecycle-live.mjs`。脚本创建临时应用，测试登录、设备/IP、封禁、充值、登出和删除账号后的令牌失效，结束时删除测试应用。

卡密专项回归：使用同样环境变量运行 `node scripts/kami-live.mjs`，覆盖并发激活、并发充值、冻结解冻、永久卡、应用隔离及分组删除。已消费的充值券不能作为卡密账号登录；冻结保留原使用状态，解冻不会恢复充值次数。

安全边界回归：运行 `node scripts/security-boundaries-live.mjs`，验证隐藏入口、防爆破的用户名变体和并发限制、云函数管理权限与管理员改密失效；自定义入口可设置 `TEST_ADMIN_ENTRY`。

文件下载回归：设置 `TEST_ADMIN_PASSWORD` 与 `TEST_APK_PATH`（测试 APK），运行 `node scripts/file-security-live.mjs`，验证附件字节一致、Range/HEAD、跨应用访问、停用和删除后的链接、上传体积限制、目录和路径穿越，以及 APK 发布状态。

后端运行 `go test ./...`；前端运行 `npm run check`、`npm test`。浏览器测试默认使用 Windows Chrome，其他环境设置 `CHROME_PATH`。

前端 `npm run test:regression` 验证应用选择修复、表单失败保留、下载错误、自定义登录入口、版本链接、编辑器资源释放、动态图标、错误提示去重、日志查询并发与删除分类，以及旧会话响应隔离。

前端 `npm run test:app-scope` 验证多标签页各自的应用选择、切换瞬间的请求归属、迟到的列表与首页响应隔离，以及显示应用内编号时编辑、删除仍使用原系统 ID。

前端 `npm run test:forms` 验证添加用户、导出、奖励、扩展文件上传、个人资料和修改密码的提交、失败重试与弹窗状态。

前端 `npm run test:settings` 验证批量 API 重定义失败后的状态恢复和状态码输入校验。真实后端的 `test:user-details` 还覆盖加密方案开关与删除、云函数运行及文件上传下载删除。

前端 `npm run test:dashboard` 验证三种屏幕宽度、明暗主题下的趋势图图例位置和整数刻度。后端 `go test ./internal/buildpool/bsdiff` 包含原程序实际生成的 10 组补丁样本，比较完整补丁字节并还原原文件，覆盖插入、删除、移动、重复候选、短文件、匹配边界和 aapt2 生成的 APK。

前端 `npm run test:dashboard-live` 使用相同的 `TEST_BASE_URL`、管理员环境变量，验证已有日志实例的首页最近操作与真实接口顺序一致。最近操作合并当前应用的后台操作和用户操作，取最新 8 条；后端集成测试验证合并、排序、数量限制及两类日志的应用隔离。

前端 `npm run test:user-details` 连接 `TEST_BASE_URL` 指定的真实后端，使用 `TEST_ADMIN_USER`、`TEST_ADMIN_PASSWORD`（以及可选 `TEST_ADMIN_ENTRY`）登录，创建独立测试应用，验证用户信息保存、扩展变量增删改、设备解绑、IP 地点管理和系统设置标签，结束后删除该测试应用。

在 PowerShell 运行 `./scripts/test-docker.ps1` 可使用独立的 auth-api-verification 项目进行 Linux、MySQL、Redis 测试。测试不会使用日常 auth-api-local 项目。集成测试需指定独立数据库；未配置外部依赖时相应用例会跳过。脚本生成的报告和截图是临时产物，可以删除。

## 实现说明

### 应用隔离与固定编号

用户、用户分组、卡密、卡密分组、版本、公告、扩展变量、扩展文件、黑名单、加密方案和云函数分别按应用分配固定编号，从 1 开始。已有 ID 列显示为“应用内编号”，接口字段为 `appRecordId`；数据库主键及接口参数 `id` 保持不变，SDK、分组关联、会话、编辑和删除继续使用系统 ID。用户搜索可选择两种编号，用户导出同时包含两列。

迁移 `0046_app_record_ids.sql` 按各应用、各类记录的原系统 ID 顺序补齐历史编号，之后通过事务和独立计数器分配。删除、筛选和翻页不会重新编号，也不会复用已删除的编号；不同应用可以同时存在编号 1。删除整个应用会清理其编号映射和计数器。直接在数据库插入业务记录时需同步维护编号；应用提供的创建、批量生成和 SDK 注册接口已统一处理。

迁移 `0045_admin_log_app_scope.sql` 为后台操作日志记录应用归属。最近操作、应用操作日志列表、操作分类和清理均限制在当前应用；修改指定应用设置的日志归属于 URL 中的目标应用。历史日志仅从已记录的应用路由和应用 ID 恢复归属，无法确定归属的记录及全局管理操作保留在全局范围，不混入任何应用。系统日志仍在系统范围管理。

扩展文件列表、分类和带应用 ID 的下载接口仅返回该应用的文件；旧的 `appid=0` 文件不再混入各应用，已有公开文件链接的处理规则保留。每个浏览器标签页使用自己当前显示的应用，请求在发起时固定应用 ID，另一个标签页切换应用不会改变它的请求范围。

后端集成测试 `TestApplicationNumbersUpgradeAndConcurrency` 验证从 44 份迁移升级后的历史归属、编号回填、并发创建、删除不复用和事务回滚；`TestRealDatabaseLifecycle` 验证 11 类记录的真实接口、搜索与导出、编辑删除的系统 ID 兼容性，以及日志列表、首页和清理的应用隔离。测试使用 `AUTH_RECOVERY_MYSQL_DSN` 指定的独立 MySQL 实例，在其中新建并清理专用临时数据库。

这是根据现存程序重建的源码，并非逐字恢复的原项目。原客户端兼容性及真实业务 APK 仍需验证。主要差异：

- 云函数使用 Goja 替代 QuickJS，无独立堆内存硬限制。查看、编辑、删除及试运行仅限超级管理员；客户端仍可按原协议调用已启用的 manual 函数。
- 云函数 HTTP 禁止访问内网、回环及云元数据地址，重定向同样受限；数据库查询仍仅供受信任脚本使用。
- SDK 按应用、来源 IP 和接口限流：克隆/重签每分钟 6 次，握手/头像 30 次，登录/注册 60 次，其余 300 次，超限返回 1017。补丁生成每进程同时执行一个任务；多个客户端共享出口 IP 时共用额度。
- 管理员与用户令牌均绑定密码版本，改密后旧令牌失效；升级前未绑定版本的管理员令牌需重新登录。主密钥仍按需生成。
- 公开安装状态接口不返回后台入口。访问后台时，前端通过 `X-Admin-Entry` 校验已知入口；自定义入口需自行保存，入口隐藏不替代登录鉴权。
- DELTA1 已按原二进制恢复后缀数组匹配（32 字节种子、最多 32 个候选）、控制流及 zlib level 9 压缩；10 组原程序样本逐字节一致。为避免 Go 1.26 及后续压缩实现变化影响补丁字节，保留 Go 1.25.11 的压缩源码及许可证。空输入报错，相同内容不生成升级补丁。真实业务 APK 和旧客户端完整更新流程仍需验收。
- 卡密账号暂不支持独立 APK 签名/克隆；卡密关联记录采用负 UID，旧数据需检查转换。
- APK 原包和扩展文件具有公开下载 URL，但下载时检查有效记录：应用停用或删除、文件删除、APK 版本下架后拒绝旧链接。APK 上传后需保存为启用版本才公开下载。头像只提供单个图片，不提供目录列表。应用继承复制策略和加密方案，不复制用户、卡密或证书。
- 差异补丁下载按应用隔离并有有效期，但链接不是用户权限凭据；公开资源不要存放秘密。客户端应通过 HTTPS 获取元数据，并核对原包和还原包的 SHA-256、APK 签名。DELTA1 本身不提供来源认证。

已完成真实 MySQL/Redis、Linux 容器及前端联调。未连接生产服务器。

## 防护、会话和自动备份

SDK 基础限流始终启用：登录每应用/IP/分钟 60 次，注册 10 次，充值 20 次，账号登录另有每分钟 30 次限制；已开启的应用防爆破策略仍保留。卡密登录与充值共享 IP、账号/设备、卡密维度限流，并在连续尝试后增加重试冷却。保留客户端原有业务错误码，拒绝文案统一，客户端协议没有变化。该措施不能代替上游网络层的 DDoS 防护。

系统设置 → 安全事件：记录登录失败、卡密拒绝、限流、签名异常和封禁拦截；同应用/IP/接口/类型每分钟最多记录一条，保留 30 天。日志不包含密码、原始卡密或登录令牌，仅超级管理员可查看。

用户详情和卡密详情 → 会话管理：查看登录 IP、最近 IP、登录时间、最近活跃和最近心跳，支持单会话下线与全部下线。客户端在下一次请求/心跳时发现会话失效；不主动修改客户端界面。升级前的会话在再次请求时进入会话索引，全部下线也撤销未进入索引的旧会话。列表的最后活跃时间在成功登录与通过验证的心跳时更新，登录时间独立保留。

系统设置 → 自动备份：默认关闭，可配置 1–720 小时间隔、保留最近 1–30 份成功备份，并选择是否包含上传文件。立即备份使用已经保存的设置。文件位于配置文件旁 `backups/`，Docker 为 `/app/runtime/backups` 持久卷；只允许超级管理员通过鉴权接口下载。保留策略仅在新备份成功后清理旧成功文件，失败备份不替代可用备份。单次最多运行 30 分钟，SQL 最多 8 GiB，归档输入及输出上限各 10 GiB。

备份包含 `database.sql`、`runtime/config.yaml`、已存在的 `runtime/data/master.key`、`manifest.json`；选择文件备份时包含 `files/uploads` 与 `files/canonical`。不会为了备份生成主密钥。Redis 会话、可再生成的差异补丁和可重新安装的本地 IP 库不备份。数据库采用一致性快照；文件按顺序读取，要求严格一致时请暂停上传、文件修改和数据库迁移后再备份。

恢复步骤：

1. 停止待恢复实例，对其当前数据另外留存。将可信备份解压到独立目录，检查 `manifest.json`。
2. 创建一个空 MySQL 数据库，将 `database.sql` 导入这个空库（例如 `mysql -u USER -p NEW_DATABASE < database.sql`）。SQL 包含同名前缀表的重建语句，请勿直接导入正在使用的数据库。
3. 恢复运行配置，修改数据库连接至新库；如归档包含主密钥，原样放回运行目录 `data/master.key`。恢复 `files/uploads` 与 `files/canonical` 至配置所指路径，并赋予服务用户读写权限。
4. 使用同版本或更新的服务正常启动，程序会先自动应用尚未完成的数据库迁移。使用独立/清空的 Redis 会话库，所有客户端重新登录。需要地域绑定时重新安装 IP 库。
5. 检查管理员登录、用户/卡密验证、文件下载和证书功能后再切换流量。

归档包含凭据和密钥，按敏感数据保管。当前提供本地备份与鉴权下载，不自动传到第三方存储；请将至少一份备份保存到其他设备，同盘备份无法应对整盘损坏。
